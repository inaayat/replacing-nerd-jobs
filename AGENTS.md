# AGENTS.md

## Cursor Cloud specific instructions

### Service: Vercel static site + serverless API

This repo is a no-build Vercel site (see `README.md` for structure/deploy). Non-obvious notes for running and testing locally:

- Dependencies install with `npm install` (there are no `npm` scripts). `node_modules/` is the only install output.
- The fully standard dev command is `vercel dev`, but it requires an interactive Vercel login and Neon secrets (`DATABASE_URL`, `NEON_AUTH_BASE_URL`) for the `api/*` serverless functions. Those secrets are not present by default.
- For local UI work without Vercel or secrets, serve the repo root as static files, e.g. `python3 -m http.server 8080`. All client-side pages work this way — notably the JSON-driven `sporcle-spinoff/` trivia platform (catalog + player) at `http://127.0.0.1:8080/sporcle-spinoff/`, and the Plot Points shell at `http://127.0.0.1:8080/plot-points/`. The `api/*` routes do NOT run under a plain static server; Plot Points live queries need `TMDB_API_KEY` (and optionally `DATABASE_URL` for result caching) via `vercel dev` or deployed env.
- TMDB access is shared: `lib/tmdb.js` is used by both A-Lister (`api/alist.js`) and Plot Points (`api/plot-points.js`). Same `TMDB_API_KEY`, same `alist_movie_cache` table (Plot Points reads/writes `raw.cast_members` for cast-with-ids; A-Lister keeps using `raw.cast` name arrays). Cache rows carry `raw.pp_v`; bump `PP_SCHEMA` in `lib/tmdb.js` when adding fields Plot Points needs so stale rows are refetched instead of silently returning zeros.
- `plot-points/query-engine.js` is imported by BOTH `api/plot-points.js` and the browser (`plot-points/app.js`), so the builder controls and the server engine share one field catalog. Keep it dependency-free ESM — no `node:` imports, no npm packages — or the browser build breaks. It deliberately lives under `plot-points/` rather than `lib/`: `middleware.js` 404s everything under `/lib/`, so a browser-imported module there is unreachable in production (this once took the whole page down). `node scripts/test-public-imports.mjs` guards against reintroducing that.
- `fortune-500/statement.js` is the one source of statement orientation (years as columns, line items as rows) for the filed pane, the practice model, and the compare scale block. Keep it import-free: `fortune-500/catalog.js` imports `STATEMENT_KEYS` from it, so an import back into `catalog.js` would be a cycle. It deliberately has no projected cells for cash or long-term debt — the sliders model an income statement, not a balance sheet.
- Fortune 500 headline payloads carry the prior filed year as a slim value map (`priorMetrics`) so a statement has a FY-1 column. Two version numbers guard stale data: `SNAPSHOT_SCHEMA` in `scripts/pull-fortune500-headlines.mjs` (refetches every filer when bumped) and `PAYLOAD_SCHEMA` in `api/fortune-500.js` (invalidates the Neon `f500_headline_cache` rows). Bump both when the payload gains a field the UI reads, or old rows quietly render as dashes.
- Vercel's Hobby plan allows at most 12 serverless functions per deployment; this repo currently uses 10. Prefer adding a `?route=` branch to an existing handler plus a rewrite in `vercel.json` before creating a new `api/*.js` file. (This is why all Plot Points endpoints live in `api/plot-points.js` and all Sticky Notes endpoints in `api/sticky-notes.js`.)
- Auth is Neon Auth only (`account.html` → JWT → `/api/*`). The old `SITE_PASSWORD` / `/private/` cookie gate was retired.

- `world-in-nyc/data/ed.geojson` and overlay GeoJSON are generated by `node scripts/build-world-in-nyc.mjs` (DCP ArcGIS election districts + political overlays) and committed. Keep `world-in-nyc/app.js`, `world-in-nyc/countries.js`, `world-in-nyc/era.js`, and `world-in-nyc/votes.js` dependency-free ESM. Do not put them under `/lib/`. Mayor 2025 ED tallies are `world-in-nyc/data/mayor-2025.json` (refresh with `node scripts/pull-world-in-nyc-mayor.mjs`).
- `sticky-notes/` v1 is a signed-in two-tier app: a pan/zoom **board** (drag, arrows, pins, resize) and a **memory** table, over one local-first store (`sticky-notes/sync.js`) that queues ops to `api/sticky-notes.js`. All mutation semantics live in the pure reducer `applyOps` in `sticky-notes/notes.js` (browser-safe, dependency-free ESM — the server imports it too); `lib/sticky-notes.js` mirrors those ops in SQL and must stay in sync. Static-server dev: open `/sticky-notes/?local=1` to skip auth (local-only store). The v0 Chrome extension in `sticky-notes/extension/` is frozen — do not port it to the v1 model without a plan.
- Every collection has exactly one wiki page (`state.wikis`, op `wiki.set`, table `sn_wiki`). Opening always works; the row is created on first edit. The page is a house-editor document (`normalizeDoc`: h1/h2/p/ul/ol/hr + bold + link pills + optional `noteId` provenance) plus a live note outline. Pull copies blocks into the body; it is not a live embed. Dead chips hide when the source note is deleted. TOC is derived at render from headings when there are at least three, never stored. Title is the collection name (`collection.rename`). Hash route `#wiki/<collectionId>` replaces the canvas; memory stays. `collection.create` accepts optional `status` — Memory "+ New collection" uses `memory` so wipe will not file an empty shell. `collection.delete` drops the wiki. Do not import an npm editor. Headings are wiki-only — `normalizeRich` on notes stays `p|ul|ol`.
- A note body is **data, not HTML**: a flat list of lines, `{ type: 'p'|'ul'|'ol', spans: [{ text, bold, href? }] }`, stored in `sn_notes.rich` (JSONB) with `note.text` as its plain projection (`• ` for bullets, renumbered `N. ` for ordered runs; link pills contribute display text only). `href` is http(s) only, ≤2048 chars (`isLoneUrl`). `normalizeNote` derives `text` from `rich` whenever `rich` is present, so memory search and the memory table can never read a stale body — and nothing needs sanitizing, because the browser builds the DOM element by element. `rich: null` means a note written before formatting existed; `noteBlocks(note)` reads those through `textToRich`, so a line typed as `- milk` renders as a real bullet. Formatting is deliberately bold + the two lists + link pills; do not grow it into a document editor. Render/read/edit live in `sticky-notes/body.js` (board, memory, and the table view consume it) — never put that module under `/lib/`. Lists are converted by hand (`toggleList`), **not** with `document.execCommand('insertUnorderedList')` — Chrome's version reaches into the list above the caret and steals its last item. Bold stays on `execCommand` so it keeps native undo. An `href` span paints as `<a class="sn-pill">` (`contenteditable=false`).
- Board ink (`state.ink`, `sn_ink`, ops `ink.upsert` / `ink.move` / `ink.delete`) is text written on the board itself, not a note. It has **no status column**, so it can never be filed, and `wipe` deletes it in both the reducer and SQL. The wipe toast's Undo re-upserts the rows it captured (`wipeTargets().ink`), because unlike notes they were destroyed rather than moved.
- Colour fills the whole card through the `--note-fill` custom property (`.sn-card { background: var(--note-fill, var(--panel)) }`), and `DEFAULT_COLOR_KEY` (`c7`, light grey) is what `createNote` stamps. A note with `colorKey: null` predates the grey and stays paper-coloured — do not backfill it.
- Anything focusable on the board is **≥16px on touch** (`.sn-card-body`, `.sn-ink`, `.sn-ab-name`, the memory filters). Below that, iOS Safari zooms the whole document on focus and never zooms back. The canvas keeps its own pan/pinch — that is a transform on `#world`, not page scale.
- The tier-1 edit bar is two groups: actions (trash / pin / colour / icon / done) and `.sn-eb-format` (bold / bullets / numbers / link). On a phone (`pointer: coarse` and `max-width: 719px`) it is one slim row of small glyphs with 44px hit slop — never a two-row 44px slab. The iOS keyboard is a **layout inset** (`keyboardLayout` in `notes.js`, applied as `html.sn-kb-inset`): the shell height eases toward `visualViewport.height` (respecting `offsetTop`) so the dotted canvas slides with the keys rather than jumping. Do not pan the world/camera to chase the caret, and do not `window.scrollTo`. `planEditSession` docks the slim bar at the bottom of that remaining canvas on the phone; desktop still floats the bar above the note. Site nav and the BOARD/MEMORY toolbar stay visible below `env(safe-area-inset-top)` while a note is focused; the guest banner can still hide (`html.sn-editing`). Popovers are positioned by `placePopover` against the **whole bar** and clamped to the canvas; they stay open after a pick, because a press that removes its own target leaves the follow-up click to land on the toolbar underneath.
- `sticky-notes/manifest.webmanifest` + `sticky-notes/icons/` make the board installable (same pattern as `amc-a-lister/`, no service worker). Regenerate the PNGs from `icons/app-icon.svg` with `npm install --no-save sharp && node scripts/generate-sticky-notes-icons.mjs`; `sticky-notes/icon.svg` stays the transparent in-page nav icon. `app.js` adds `.sn-standalone` to `<html>` when installed (matchMedia, or `navigator.standalone` on iOS) and the nav compacts.
- Sticky Notes board chrome is deliberately two-tier, and both tiers are toggled with the `hidden` attribute: the tier-1 edit bar (`#editbar`, trash/pin/colour/done) is screen-space `position: fixed` and exists only while a note is being edited; the tier-2 selection bar (`#actionbar`) is docked at the bottom of the canvas whenever a selection exists. `app.css` sets `[hidden] { display: none !important }` because nearly all of this chrome is a flex box, which would otherwise beat the user-agent `display: none`. Chrome buttons are wired through `onPress` in `board.js` (act on `pointerdown` with the default prevented, `click` kept for keyboards) so pressing one cannot blur the note being edited and commit the edit out from under the press.
- Sticky Notes input is pointer-type aware and lives entirely in the one `pointerdown`/`pointermove`/`pointerup` trio on `#viewport`. Mouse: 4px drag slop, rubber-band on empty board, click-to-edit. Touch: 8px slop, one-finger pan on empty board, two-finger pinch (`drag.kind === 'pinch'`), long-press (400ms) to enter multi-select, double-tap to create; tap-to-edit deliberately does **not** select, so the selection bar never appears from a single tap. `zoomAt` in `notes.js` is the one anchor-preserving zoom used by wheel, buttons, and pinch — keep it there and tested rather than reimplementing the math. Anything that measures "is this on screen" must use `visualViewport`, not `window.innerHeight`, or it will sit under a phone keyboard.
- Sticky Notes layout has one breakpoint that matters: at ≥1100px `#memory-pane` is a permanent right sidebar (collapsible to a rail, remembered in `localStorage`) and the Board/Memory tabs are hidden; below that the same element is the Memory tab. `memory.js` renders into that one element either way — do not fork it into two views. The board itself has a canvas | table toggle immediately right of `+` (`localStorage['sticky-notes-board-view']`); `#table-pane` replaces `#viewport` and shows board-status notes only (`sticky-notes/table.js`). If that key is unset, `defaultBoardView` opens the **table** on coarse/narrow (≤720) and the canvas on desktop — a stored pick always wins. Viewing the table writes no ops. New notes on a phone use `NOTE_W_PHONE` × `NOTE_H_PHONE` (desktop stays `NOTE_W_DEFAULT` × `NOTE_H_DEFAULT`). The toolbar is left-aligned (`.sn-toolbar { justify-content: flex-start }`; `.sn-toolbar-actions` has no `margin-left: auto`).
- `ai-buildout/` is a static page plus a committed EDGAR snapshot for seven issuers. Keep `ai-buildout/extract.js` dependency-free ESM (it is imported by the browser). Do not fold its lease/debt-proceeds tags into the Fortune 500 473-company snapshot. Refresh with `node scripts/pull-ai-buildout.mjs`; bump `SNAPSHOT_SCHEMA` in `ai-buildout/catalog.js` when the slim payload gains a field.
