## Cursor Cloud specific instructions

### Service: Vercel static site + serverless API

This repo is a no-build Vercel site (see `README.md` for structure/deploy). Non-obvious notes for running and testing locally:

- Dependencies install with `npm install` (there are no `npm` scripts). `node_modules/` is the only install output.
- The fully standard dev command is `vercel dev`, but it requires an interactive Vercel login and Neon secrets (`DATABASE_URL`, `NEON_AUTH_BASE_URL`) for the `api/*` serverless functions. Those secrets are not present by default.
- For local UI work without Vercel or secrets, serve the repo root as static files, e.g. `python3 -m http.server 8080`. All client-side pages work this way — notably the JSON-driven `sporcle-spinoff/` trivia platform (catalog + player) at `http://127.0.0.1:8080/sporcle-spinoff/`, the Plot Points shell at `http://127.0.0.1:8080/plot-points/`, Takeout at `http://127.0.0.1:8080/takeout/`, the ASC 606 decision tree at `http://127.0.0.1:8080/asc-606/`, and Wedding at `http://127.0.0.1:8080/wedding/?local=1`. The `api/*` routes do NOT run under a plain static server; Plot Points live queries need `TMDB_API_KEY` (and optionally `DATABASE_URL` for result caching) via `vercel dev` or deployed env.
- TMDB access is shared: `lib/tmdb.js` is used by both A-Lister (`api/alist.js`) and Plot Points (`api/plot-points.js`). Same `TMDB_API_KEY`, same `alist_movie_cache` table (Plot Points reads/writes `raw.cast_members` for cast-with-ids; A-Lister keeps using `raw.cast` name arrays). Cache rows carry `raw.pp_v`; bump `PP_SCHEMA` in `lib/tmdb.js` when adding fields Plot Points needs so stale rows are refetched instead of silently returning zeros.
- `plot-points/query-engine.js` is imported by BOTH `api/plot-points.js` and the browser (`plot-points/app.js`), so the builder controls and the server engine share one field catalog. Keep it dependency-free ESM — no `node:` imports, no npm packages — or the browser build breaks. It deliberately lives under `plot-points/` rather than `lib/`: `middleware.js` 404s everything under `/lib/`, so a browser-imported module there is unreachable in production (this once took the whole page down). `node scripts/test-public-imports.mjs` guards against reintroducing that.
- `takeout/` is a static API → Excel picker. `flatten.js`, `catalog.js`, and `workbook.js` are browser-safe ESM (no `node:` imports). Do not put them under `/lib/`. There is no new Vercel function and no generic URL proxy — custom URLs fetch from the browser; CORS failures tell you to paste JSON. Yahoo daily prices reuse `/api/f500-prices` when that route is deployed.
- `asc-606/` is a static decision tree for Topic 606. `tree.js`, `engine.js`, `citations.js`, `glossary.js`, and `quiz.js` are browser-safe ESM — do not put them under `/lib/`. The guided walk is a connected path: each selected answer labels the line to the next question, and earlier nodes rewind the walk. Keep beginner translations in `glossary.js` instead of duplicating definitions in the UI. No new Vercel function. Hover chips show short official excerpts only; do not commit the full Codification PDF.
- `fortune-500/statement.js` is the one source of statement orientation (years as columns, line items as rows) for the filed pane, the practice model, and the compare scale block. Keep it import-free: `fortune-500/catalog.js` imports `STATEMENT_KEYS` from it, so an import back into `catalog.js` would be a cycle. It deliberately has no projected cells for cash or long-term debt — the sliders model an income statement, not a balance sheet.
- Fortune 500 headline payloads carry the prior filed year as a slim value map (`priorMetrics`) so a statement has a FY-1 column. Two version numbers guard stale data: `SNAPSHOT_SCHEMA` in `scripts/pull-fortune500-headlines.mjs` (refetches every filer when bumped) and `PAYLOAD_SCHEMA` in `api/fortune-500.js` (invalidates the Neon `f500_headline_cache` rows). Bump both when the payload gains a field the UI reads, or old rows quietly render as dashes.
- Vercel's Hobby plan allows at most 12 serverless functions per deployment; this repo currently uses 11. Prefer adding a `?route=` branch to an existing handler plus a rewrite in `vercel.json` before creating a new `api/*.js` file. (This is why all Plot Points endpoints live in `api/plot-points.js` and all Sticky Notes endpoints in `api/sticky-notes.js`.)
- Auth is Neon Auth only (`account.html` → JWT → `/api/*`). The old `SITE_PASSWORD` / `/private/` cookie gate was retired.

- Every collection has exactly one wiki page (`state.wikis`, op `wiki.set`, table `sn_wiki`). Opening always works; the row is created on first edit. The page is a house-editor document (`normalizeDoc`: h1/h2/p/ul/ol/hr + bold + link pills + optional `noteId` provenance) plus a live note outline. Pull copies blocks into the body; it is not a live embed. Dead chips hide when the source note is deleted. TOC is derived at render from headings when there are at least three, never stored. Title is the collection name (`collection.rename`). Hash route `#wiki/<collectionId>` replaces the canvas; memory stays. `collection.create` accepts optional `status` — Memory "+ New collection" uses `memory` so wipe will not file an empty shell. `collection.delete` drops the wiki. Do not import an npm editor. Headings are wiki-only — `normalizeRich` on notes stays `p|ul|ol`.
- A note body is **data, not HTML**: a flat list of lines, `{ type: 'p'|'ul'|'ol', spans: [{ text, bold, href? }] }`, stored in `sn_notes.rich` (JSONB) with `note.text` as its plain projection (`• ` for bullets, renumbered `N. ` for ordered runs; link pills contribute display text only). `href` is http(s) only, ≤2048 chars (`isLoneUrl`). `normalizeNote` derives `text` from `rich` whenever `rich` is present, so memory search and the memory table can never read a stale body — and nothing needs sanitizing, because the browser builds the DOM element by element. `rich: null` means a note written before formatting existed; `noteBlocks(note)` reads those through `textToRich`, so a line typed as `- milk` renders as a real bullet. Formatting is deliberately bold + the two lists + link pills; do not grow it into a document editor. Render/read/edit live in `sticky-notes/body.js` (board, memory, and the table view consume it) — never put that module under `/lib/`. Lists are converted by hand (`toggleList`), **not** with `document.execCommand('insertUnorderedList')` — Chrome's version reaches into the list above the caret and steals its last item. Bold stays on `execCommand` so it keeps native undo. An `href` span paints as `<a class="sn-pill">` (`contenteditable=false`).
- A note may also carry one compact `media` attachment (`sn_notes.media` JSONB), separate from its rich body: normalized source/canonical URLs, a server-unfurled thumbnail/title, a derived kind, and `position: 'before'|'after'`. Old attachments normalize to `after`; the picker defaults new ones to `before`, which leaves the editable body below the image. Direct images/video, Pinterest, Instagram, TikTok, YouTube, and generic Open Graph images are supported. Never persist or trust an embed URL — `localMediaDetails` derives official embeds from the normalized source. Pinterest remains a still; social video remains behind a play control. `renderMedia` in `sticky-notes/body.js` builds every element safely and keeps the preview inside the coloured card.
- Icon tags can be built-in SVG keys (including `wedding`) or named custom image tags (`custom:<id>`). Every built-in label can be overridden through the picker’s Edit tag names view (`state.legend.icons`; `sn_legend kind = 'icon'`). Custom definitions live in `state.legend.customIcons` and `sn_legend` rows with `kind = 'custom-icon'` + `image_url`; notes still store only `iconKey`. Images must be http(s), are rendered by `renderIcon` (never injected as markup), and current built-in/custom labels are included in Memory search. Deleting a custom definition clears it from tagged notes in both the reducer and SQL. Typing `#tag` anywhere in a note body on commit promotes matches: known icon keys/labels become `iconKey`, everything else becomes compact pills in `note.tags` (stored in `sn_notes.tags` JSONB) rendered above the body; the `#…` tokens leave the stored text.

It has **no status column**, so it can never be filed, and `wipe` deletes it in both the reducer and SQL. The wipe toast's Undo re-upserts the rows it captured (`wipeTargets().ink`), because unlike notes they were destroyed rather than moved.

- Sticky Notes board chrome is deliberately two-tier, and both tiers are toggled with the `hidden` attribute: the tier-1 edit bar (`#editbar`, trash/pin/colour/done) is screen-space `position: fixed` and exists only while a note is being edited; the tier-2 selection bar (`#actionbar`) is docked at the bottom of the canvas whenever a selection exists. `app.css` sets `[hidden] { display: none !important }` because nearly all of this chrome is a flex box, which would otherwise beat the user-agent `display: none`. Anything that measures "is this on screen" must use `visualViewport`, not `window.innerHeight`, or it will sit under a phone keyboard.
