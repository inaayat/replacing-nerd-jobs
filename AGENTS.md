## Cursor Cloud specific instructions

### Service: Vercel static site + serverless API

This repo is a no-build Vercel site (see `README.md` for structure/deploy). Non-obvious notes for running and testing locally:

- Dependencies install with `npm install` (there are no `npm` scripts). `node_modules/` is the only install output.
- The fully standard dev command is `vercel dev`, but it requires an interactive Vercel login and Neon secrets (`DATABASE_URL`, `NEON_AUTH_BASE_URL`) for the `api/*` serverless functions. Those secrets are not present by default.
- For local UI work without Vercel or secrets, serve the repo root as static files, e.g. `python3 -m http.server 8080`. All client-side pages work this way — notably the JSON-driven `sporcle-spinoff/` trivia platform (catalog + player) at `http://127.0.0.1:8080/sporcle-spinoff/`, the Plot Points shell at `http://127.0.0.1:8080/plot-points/`, Takeout at `http://127.0.0.1:8080/takeout/`, the ASC 606 decision tree at `http://127.0.0.1:8080/asc-606/`, Brag Book at `http://127.0.0.1:8080/brag-book/?local=1`, Wedding at `http://127.0.0.1:8080/wedding/?local=1`, and Seattle property taxes at `http://127.0.0.1:8080/seattle-property-taxes/`. The `api/*` routes do NOT run under a plain static server; Plot Points live queries need `TMDB_API_KEY` (and optionally `DATABASE_URL` for result caching) via `vercel dev` or deployed env. GIS and Socrata lookups on Seattle property taxes run from the browser; tax-roll history needs the `/api/kc-dashboard` rewrite (deployed Vercel only).
- TMDB access is shared: `lib/tmdb.js` is used by both A-Lister (`api/alist.js`) and Plot Points (`api/plot-points.js`). Same `TMDB_API_KEY`, same `alist_movie_cache` table (Plot Points reads/writes `raw.cast_members` for cast-with-ids; A-Lister keeps using `raw.cast` name arrays). Cache rows carry `raw.pp_v`; bump `PP_SCHEMA` in `lib/tmdb.js` when adding fields Plot Points needs so stale rows are refetched instead of silently returning zeros.
- `plot-points/query-engine.js` is imported by BOTH `api/plot-points.js` and the browser (`plot-points/app.js`), so the builder controls and the server engine share one field catalog. Keep it dependency-free ESM — no `node:` imports, no npm packages — or the browser build breaks. It deliberately lives under `plot-points/` rather than `lib/`: `middleware.js` 404s everything under `/lib/`, so a browser-imported module there is unreachable in production (this once took the whole page down). `node scripts/test-public-imports.mjs` guards against reintroducing that.
- `takeout/` is a static API → Excel picker. `flatten.js`, `catalog.js`, and `workbook.js` are browser-safe ESM (no `node:` imports). Do not put them under `/lib/`. There is no new Vercel function and no generic URL proxy — custom URLs fetch from the browser; CORS failures tell you to paste JSON. Yahoo daily prices reuse `/api/f500-prices` when that route is deployed.
- `asc-606/` is a static decision tree for Topic 606. `tree.js`, `engine.js`, `citations.js`, `glossary.js`, and `quiz.js` are browser-safe ESM — do not put them under `/lib/`. Keep beginner translations in `glossary.js` instead of duplicating definitions in the UI. No new Vercel function. Hover chips show short official excerpts only; do not commit the full Codification PDF.

- A note body is **data, not HTML**: a flat list of lines, `{ type: 'p'|'ul'|'ol', spans: [{ text, bold, href? }] }`, stored in `sn_notes.rich` (JSONB) with `note.text` as its plain projection (`• ` for bullets, renumbered `N. ` for ordered runs; link pills contribute display text only). `href` is http(s) only, ≤2048 chars (`isLoneUrl`). `normalizeNote` derives `text` from `rich` whenever `rich` is present, so memory search and the memory table can never read a stale body — and nothing needs sanitizing, because the browser builds the DOM element by element. `rich: null` means a note written before formatting existed; `noteBlocks(note)` reads those through `textToRich`, so a line typed as `- milk` renders as a real bullet. Formatting is deliberately bold + the two lists + link pills; do not grow it into a document editor. Lists are converted by hand (`toggleList`), **not** with `document.execCommand('insertUnorderedList')` — Chrome's version reaches into the list above the caret and steals its last item. Bold stays on `execCommand` so it keeps native undo. An `href` span paints as `<a class="sn-pill">` (`contenteditable=false`).
- A note may also carry one compact `media` attachment (`sn_notes.media` JSONB), separate from its rich body: normalized source/canonical URLs, a server-unfurled thumbnail/title, a derived kind, and `position: 'before'|'after'`. New attachments default to `after` (text above the preview); clicking the preview or below it on the card moves the body under it (`before`). Direct images/video, Pinterest, Instagram, TikTok, YouTube, and generic Open Graph images are supported. Never persist or trust an embed URL — `localMediaDetails` derives official embeds from the normalized source. Pinterest remains a still; YouTube/TikTok stay behind a play control. Instagram is a still or placeholder only — never iframe `/embed/`, which letterboxes a mini profile (View profile, audio) inside the card. `renderMedia` in `sticky-notes/body.js` builds every element safely and keeps the preview inside the coloured card — **except** when the attachment is the only thing on the note (`noteIsOnlyMedia` in `notes.js`, and `mediaShowsStill` in `body.js` for whether it paints a real still rather than a placeholder or embed, which for Instagram depends on the auth token). Then the board adds `.sn-card.is-photo`: no padding, border, or paper, and the image wears the card's own radius. Do not add `overflow: hidden` there — the pin hangs over the top edge; the media host clips the image and inherits the radius to do it. A note being edited always gets its card back, since an empty body is nowhere to type. **The preview is not a link on touch** (`pointer: coarse` sets `pointer-events: none` on `.sn-media-link` / `.sn-media-play`, leaving only the centred play glyph): a finger on a picture is nearly always trying to move the note, so presses fall through to the board's drag machinery and a `.sn-media-open` corner chip is the deliberate way out to the source. A mouse still clicks the preview, and now also drags the note by it — hence `draggable = false` on the image and the click swallowed within `CLICK_AFTER_DRAG_MS` of a move.

- Sticky Notes board chrome is deliberately two-tier, and both tiers are toggled with the `hidden` attribute: the tier-1 edit bar (`#editbar`, trash/pin/colour/done) is screen-space `position: fixed` and exists only while a note is being edited; the tier-2 selection bar (`#actionbar`) is docked at the bottom of the canvas whenever a selection exists. `app.css` sets `[hidden] { display: none !important }` because nearly all of this chrome is a flex box, which would otherwise beat the user-agent `display: none`. - Sticky Notes input is pointer-type aware and lives entirely in the one `pointerdown`/`pointermove`/`pointerup` trio on `#viewport`. Mouse: 4px drag slop, rubber-band on empty board, click-to-edit. Tap-to-edit deliberately does **not** select, so the selection bar never appears from a single tap. Touch has two ways to resize a note. **Both fingers inside the same card pinch that note** (`pinchTarget` picks note vs board; `pinchNoteSize` scales w/h together from the spread the fingers started with, so pinching back returns the original size, and the height stops when the width clamps); two fingers anywhere else zoom the board, which also keeps its ± buttons for a note too big to pinch around. A note pinch anchors the top-left, does not move the note, and commits one `note.resize` when the first finger lifts. The other way in is the 44px corner handle on the selected or editing card, not the 14px hover grip — on any coarse pointer (`canStartResize`), because a tablet has no hover either. `zoomAt` in `notes.js` is the one anchor-preserving zoom used by wheel, buttons, and pinch — keep it there and tested rather than reimplementing the math; `pinchStep` (zoom about the fingers' midpoint plus that midpoint's own travel, so two fingers zoom and drag in one gesture) and `pinchAfterLift` (three fingers re-seed against the two still down; the last finger hands off to a pan instead of freezing the board) live beside it. A finger can lift over `#editbar` or `#compose`, which are **outside** `#viewport`, so the `pointers` map is also pruned by a window-level `pointerup`/`pointercancel` — without it a forgotten finger makes the next single touch a phantom pinch. Anything that measures "is this on screen" must use `visualViewport`, not `window.innerHeight`, or it will sit under a phone keyboard.
