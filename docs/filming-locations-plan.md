# Establishing Shot — product plan

Status: **plan only** — nothing built yet
Site: `/establishing-shot/` on [inaayat.xyz](https://inaayat.xyz) (this repo)
Auth: **none.** Fully static, no serverless function, no Neon.

v1 is one neighborhood: the Upper West Side from **W 60th to W 96th**. Not
Manhattan, not "NYC filming locations." The bounding box is the product
decision, and every data choice below gets easier because of it.

---

## One sentence

A map of thirty-six Upper West Side blocks showing both the famous scenes shot
there and where film crews actually park their trucks — as two honest layers,
not one guessed-at answer.

## The bounding box, precisely

Everything in v1 must be inside this rectangle, and both the pull script and
the tests should enforce it:

```
north  W 96th Street
south  W 60th Street (Columbus Circle edge)
east   Central Park West (park side included — Bethesda-ward shots are Central
       Park's problem, not v1's)
west   Riverside Drive (Riverside Park edge included)
```

Roughly `[-73.990, 40.769]` to `[-73.958, 40.796]`. The avenues in scope are
Central Park West, Columbus, Amsterdam, Broadway, West End, and Riverside;
the cross streets are W 60 through W 96.

**Do not filter by ZIP code.** I checked: filtering permits on
`zipcode_s like '%10024%'` returns rows whose held parking is *5 Avenue between
E 76 and E 79* — a permit row carries a comma-joined list of every ZIP it
touches, so an East Side shoot that also parked a truck on the West Side lands
in the result. Filter on the **parsed street segments** instead (see below).

## What the data actually looks like (probed, not assumed)

I queried both datasets before writing this, and two things differ from the
usual advice about them.

**Film Permits — `tg4x-b46p`** ([docs](https://data.cityofnewyork.us/City-Government/Film-Permits/tg4x-b46p))

| Reality | Consequence |
|---------|-------------|
| **18,775 rows total; 9,515 in Manhattan; earliest `startdatetime` is 2023-01-01** | This is a **rolling window**, not 100k rows back to 2011. There is no deep history to mine, and rows will age out from under us — which is the argument for committing a snapshot. |
| Manhattan categories: Television 3,094 · Theater 2,664 · Film 1,211 · Commercial 1,069 · Still Photography 766 · WEB 527 | Theater is Broadway load-in/load-out and mostly Midtown; **filter it out** or the UWS map inherits noise. `subcategoryname` (`Episodic series`, `Cable-episodic`, `Feature`, `Pilot`) is the useful grain. |
| `parkingheld` packs many segments in one string, comma-separated, with **irregular internal whitespace**: `"WEST   88 STREET between WEST END AVENUE and RIVERSIDE DRIVE,  WEST END AVENUE between WEST   89 STREET and WEST   86 STREET, …"` | Explode to one row per segment before anything else. Collapse runs of spaces. Note the third example spans 89→86 — **cross streets are not in geographic order**, so a parser must not assume from < to. |
| No production title, ever | Layer B is anonymous by construction. Do not imply otherwise in the UI. |
| `Access-Control-Allow-Origin: *` | A live browser fetch *would* work. We still snapshot, for stability and because the rolling window silently drops history. |

**Street Centerline (CSCL) — `inkn-q76z`**

| Reality | Consequence |
|---------|-------------|
| **No from/to cross-street columns.** The exposed schema has `physicalid`, `street_name`, `full_street_name`, house-number ranges, `l_zip`/`r_zip`, `the_geom` — and no bounding-node names. | The "segments already know their cross streets" plan does not work on this dataset. Match by street name plus geometry: take the named street's segments, find where the two cross streets intersect it, keep the piece between. |
| Names are split and oddly spaced: `street_name` is `"86"` or `"RIVERSIDE"`, `full_street_name` is `"W  86 ST"` (two spaces) | One shared normalizer has to handle both sides: `"WEST   86 STREET"` → `"W 86 ST"`. This function is the single riskiest piece of code in the project and deserves the most tests. |
| `the_geom` is a `MultiLineString`, already block-length in the UWS | Good news: on this grid, one CSCL row ≈ one block face. Cross-street math is mostly picking the right rows, not splitting lines. |
| Segments are duplicated per direction/roadbed in places | Dedupe on (normalized street, block) when counting, or Broadway double-counts. |

Because scope is 36 blocks, the committed centerline subset is small — a few
hundred segments, well under the size of `world-in-nyc/data/ed.geojson`.

## Two layers, no join

The temptation is to guess which permit was which show. v1 refuses.

```
  Layer A — Famous scenes            Layer B — Where crews actually work
  ─────────────────────             ──────────────────────────────────
  hand-curated points               permit counts per block face
  title · year · scene note         choropleth on the street lines
  60–80 UWS entries                 anonymous, category-filtered
  "Cafe Lalo, You've Got Mail"      "W 88th, 14 shoots since 2023"
```

Both are interesting alone, and the contrast between them *is* the product:
the blocks tourists visit and the blocks that get closed for trucks are not
the same blocks. Layer A is editorial. Layer B is measurement. Mixing them
into one "this permit was Only Murders" claim would put a guess where the map
currently shows a fact.

The probabilistic matcher (cluster permits into campaigns, score against
production date windows) is **slice 5 at the earliest**, and it does not ship
without a bridge source to validate against and a visible confidence badge.

## Layer A — the curated file

Hand-written, reviewed by eye, one entry per location. The UWS has on the
order of 60–80 genuinely notable ones. Seed set to start from: the Dakota,
55 Central Park West (the *Ghostbusters* Dana Barrett building — the firehouse
itself is Tribeca and belongs to a later slice), Cafe Lalo and Zabar's for
*You've Got Mail*, the Ansonia, Lincoln Center, the Museum of Natural History,
the Arcanum/Only Murders exteriors, Tom's Restaurant (which is W 112th — out
of the box, and a good first test that the box is enforced).

```json
{
  "id": "the-dakota",
  "name": "The Dakota",
  "address": "1 W 72nd St",
  "lngLat": [-73.9765, 40.7767],
  "segmentId": "…",
  "credits": [
    { "title": "Rosemary's Baby", "year": 1968, "kind": "film", "note": "The Bramford exterior." }
  ],
  "sources": ["https://…"]
}
```

Rules that keep it honest: every credit carries a source link; `lngLat` is
hand-checked against the building, not geocoded and trusted; a location that
"looks like" the UWS but is out of the box is simply not in the file yet.

## Layer B — permits to blocks

Pipeline, all of it in `scripts/pull-filming-locations.mjs`, all output
committed:

1. Pull Manhattan permits from `tg4x-b46p`.
2. Drop `Theater`, and (probably) `Still Photography` — decide by looking.
3. Explode `parkingheld` into one record per `street between a and b`.
4. Normalize street names; keep only segments whose street and cross streets
   are inside the box.
5. Resolve each to CSCL segment ids; write `segments.geojson` (geometry) plus
   `permits.json` (counts and date ranges per segment id, by category).
6. Stamp `SNAPSHOT_SCHEMA` and a `pulledAt`, same convention as
   `ai-buildout/catalog.js` and the Fortune 500 headline snapshot. Bump the
   schema when the payload gains a field the UI reads.

Segments that fail to resolve get written to an `unmatched` list with counts,
not silently dropped. That list is how the normalizer gets better, and it is
the thing to read before expanding the box.

## Layout

```
/establishing-shot/
├── index.html          ← map shell, layer toggles, detail rail
├── app.css
├── app.js              ← MapLibre wiring
├── segments.js         ← ParkingHeld parser + name normalizer (pure, tested)
├── catalog.js          ← curated-location access, SNAPSHOT_SCHEMA
├── icon.svg
└── data/
    ├── locations.json      ← Layer A, hand-written
    ├── segments.geojson    ← CSCL subset, generated
    └── permits.json        ← counts per segment, generated
```

`scripts/pull-filming-locations.mjs` generates the two files under `data/`.
`scripts/test-filming-locations.mjs` tests the parser, the normalizer, the
box filter, and the count rollups.

Site conventions this has to respect:

- Browser modules stay under `/establishing-shot/`. **Nothing goes in `/lib/`** —
  `middleware.js` 404s that path in production, and
  `node scripts/test-public-imports.mjs` guards it.
- `segments.js` and `catalog.js` stay dependency-free ESM with no `node:`
  imports, because the pull script and the browser both import them.
- No new `api/*.js`. The Hobby plan caps deployments at 12 functions and this
  repo is at 10.

## Build in slices

### Slice 1 — the box, on a map, with famous places
- Static page, MapLibre + OpenFreeMap positron, locked to the UWS box.
- `data/locations.json` with 15–20 hand-checked entries (not all 80).
- Click a pin → rail with title, year, scene note, source link.
- No permits yet. This ships as a real, useful page on its own.

### Slice 2 — the parser
- `segments.js`: `parkingheld` → segment records, and the name normalizer.
- `scripts/test-filming-locations.mjs` with the real strings from this doc as
  fixtures, including the reversed 89→86 case and the double-space names.
- Still no map change. The parser is provable without pixels.

### Slice 3 — permit density layer
- Pull script writes `segments.geojson` + `permits.json`; both committed.
- Layer toggle: Famous / Crews / Both. Street lines shaded by permit count.
- Category and date-range filters. `unmatched` count shown in an About panel —
  if the map is only 80% of the permits, say so.

### Slice 4 — fill out the curation
- Curated file up to the full 60–80. Search box over titles and locations.
- Deep links (`#loc/the-dakota`) so a location is shareable.

### Slice 5 — expand the box, then maybe match
- Expansion first: W 96th–W 110th, or south to Midtown West. The parser and
  the box filter are what make this cheap; nothing else should need changing.
- Only after that, and only with a bridge source (published daily filming
  schedules, which carry title + street + date) to validate against, consider
  campaign clustering and title matching — behind a confidence badge.

**Out of scope for a long time:** every borough, permits older than the
rolling window, user submissions, accounts, anything that needs a server.

## Still open (does not block slice 1)

- Whether `Still Photography` and `Commercial` belong in the density layer or
  behind a separate toggle.
- Whether the density unit is permit *rows* or *shoot days* (a permit spans
  a date range; days are the fairer measure and cost one more field).
- Choropleth on street lines vs. a block-polygon fill. Lines are honest to the
  data (parking is on a street, not in a block); polygons read better zoomed out.
- Whether the curated file eventually gets a Wikidata P915 pass to suggest
  candidates for a human to accept — suggestion only, never auto-insert.
- Homepage tile and where this sits relative to `/world-in-nyc/`, which is the
  other map on the site and should probably share visual language.
